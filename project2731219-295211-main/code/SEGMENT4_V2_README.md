# 赛段4 V2 规则实现总结

## 一、新规则核心变化

### 原规则
- 限高杆**固定**在左道和右道
- 中道**一定**没有限高杆
- 中道通过小口（y=8.6~9.1）进出
- 小口位置由 mid_open 参数决定（0=左，1=右）

### 新规则  
- **两个限高杆随机分布在三条道中的任意两条**
- **没有限高杆的道只能通过 y=8.6~9.1 的小口进出**
- 有限高杆的道正常通过（需要蹲姿过杆）
- 新增参数 `no_bar_lane` (1/2/3) 表示哪条道没有限高杆

## 二、三种可能情况详解

### 情况 1：左道无杆 (no_bar_lane=1)
```
布局：
  左道：无杆 ──┐
  中道：有杆    ├── 两个限高杆
  右道：有杆 ──┘

小口位置：
  固定在中道左侧 (x ≈ 0.35)
  
访问策略：
  左道 → 通过小口进出（y=8.85 横穿）
  中道 → 正常通过，需蹲姿过杆
  右道 → 正常通过，需蹲姿过杆

访问顺序：
  L(小口) → M(有杆) → R(有杆) → 桥
```

### 情况 2：中道无杆 (no_bar_lane=2) **原规则**
```
布局：
  左道：有杆 ──┐
  中道：无杆    ├── 两个限高杆在左右
  右道：有杆 ──┘

小口位置：
  由 mid_open 参数决定
  - mid_open=0 → 小口在中道左侧 (x ≈ 0.35)
  - mid_open=1 → 小口在中道右侧 (x ≈ 1.65)
  
访问策略：
  左道 → 正常通过，需蹲姿过杆
  中道 → 通过小口进出（y=8.85 横穿）
  右道 → 正常通过，需蹲姿过杆

访问顺序：
  - mid_open=0: L(有杆) → M(小口左) → R(有杆) → 桥
  - mid_open=1: L(有杆) → R(有杆) → M(小口右) → 桥
```

### 情况 3：右道无杆 (no_bar_lane=3)
```
布局：
  左道：有杆 ──┐
  中道：有杆    ├── 两个限高杆
  右道：无杆 ──┘

小口位置：
  固定在中道右侧 (x ≈ 1.65)
  
访问策略：
  左道 → 正常通过，需蹲姿过杆
  中道 → 正常通过，需蹲姿过杆
  右道 → 通过小口进出（y=8.85 横穿）

访问顺序：
  L(有杆) → M(有杆) → R(小口) → 桥
```

## 四、实现关键点

### 4.1 小口位置推导逻辑

```python
def _get_opening_x(no_bar_lane, mid_open):
    """根据无杆道和开口侧推导小口 x 坐标"""
    if no_bar_lane == "left":
        # 左道无杆 → 小口在中道左侧
        return 0.35
    elif no_bar_lane == "right":
        # 右道无杆 → 小口在中道右侧
        return 1.65
    elif no_bar_lane == "mid":
        # 中道无杆 → 由 mid_open 决定
        return 0.35 if mid_open == "left" else 1.65
```

**规律总结**：
- 左道无杆 → 小口一定在左侧（因为小口在左道右侧=中道左侧）
- 右道无杆 → 小口一定在右侧（因为小口在右道左侧=中道右侧）
- 中道无杆 → mid_open 参数决定

### 4.2 访问顺序决策逻辑

```python
def _determine_lane_order(no_bar_lane, mid_open):
    """决定三条道的访问顺序"""
    if no_bar_lane == "left":
        return ["left", "mid", "right"]
    elif no_bar_lane == "right":
        return ["left", "mid", "right"]  
    elif no_bar_lane == "mid":
        # 中道无杆时根据 mid_open 决定
        if mid_open == "left":
            return ["left", "mid", "right"]  # 从左进中道
        else:
            return ["left", "right", "mid"]  # 从右进中道
```

**决策依据**：
- 尽量让小口连接的两条道相邻访问，减少无效横移
- 左道无杆：L(小口)→M，顺序 L→M→R
- 右道无杆：M→R(小口)，顺序 L→M→R
- 中道无杆：
  - 小口在左 → L→M(小口)→R
  - 小口在右 → L→R→M(小口)

### 4.3 状态机分类

#### 有杆道状态机（原 _route_general_lane）
- 进入 → 转北 → 对齐 → **进入蹲姿区** → 向北走低姿态 → **站起** → 撞目标
- 转南 → 对齐 → **进入蹲姿区** → 向南走低姿态 → **站起** → 返回底部横道

#### 无杆道状态机（新 _route_opening_lane）
- 走到小口高度(y=8.85) → 横穿小口进入 → 转北 → 对齐 → 向北到目标 → 撞击
- 转南 → 对齐 → 向南返回小口 → 横穿小口出去 → 继续向南到底部横道

**关键差异**：
- 无杆道：无蹲姿动作，y=8.85 横穿进出
- 有杆道：y=9.0~10.3 蹲姿通过

### 4.4 足球特殊处理

```python
if target == "football":
    if _has_bar(_current_lane):
        # 有杆道的足球：保持低姿态短退 + 低姿态返回过杆
        _set_state(S["LANE_FOOTBALL_LOW_BACKUP"], ...)
    else:
        # 无杆道的足球：正常后退即可
        _set_state(S["OPENING_BACKUP"], ...)
```

**原因**：
- 有杆道：足球撞击位置(y≈11.0)在杆后，返回时必须蹲姿过杆
- 无杆道：无杆阻挡，直接后退即可

## 十、常见问题 FAQ

### Q1: mid_open 参数在 no_bar_lane≠2 时还有用吗？
**A**: 没有实际作用。只有当 no_bar_lane=2（中道无杆）时，mid_open 才决定小口位置。其他情况下小口位置是固定的。

### Q2: 为什么访问顺序不是总 L→M→R？
**A**: 当 no_bar_lane=2 且 mid_open=1 时，为了从右道通过小口进中道，需要先访问右道，所以顺序是 L→R→M。

### Q3: 中道有杆时怎么处理？
**A**: 中道有杆时（no_bar_lane≠2），使用 _route_general_lane() 状态机，与左右道的有杆逻辑相同，需要蹲姿通过。

### Q4: 两个连续的无杆道怎么办？
**A**: 实际上不会出现。因为三条道中恰好两条有杆，一条无杆，所以最多只有一条无杆道。

### Q5: 小口的 y 范围是 8.6~9.1，为什么代码用 8.85？
**A**: 8.85 是中点位置，留有上下 ±0.25m 的余量，既能确保通过小口，又能避免撞墙。

### Q6: 测试时如何模拟不同的 no_bar_lane？
**A**: 修改命令行参数的第 5 个整数（1/2/3），对应左/中/右道无杆。

## 十一、总结

### 核心改动
1. **新增参数**：no_bar_lane (1/2/3)
2. **新增函数**：_needs_opening(), _get_opening_x(), _route_opening_lane()
3. **新增状态**：OPENING_* 系列（12 个状态）
4. **修改逻辑**：访问顺序、状态分发、蹲姿判断

### 设计原则
- **向后兼容**：原文件保持不变
- **代码复用**：最大化复用原有函数
- **清晰分离**：有杆道/无杆道状态机分离
- **可测试性**：参数驱动，便于逻辑测试

### 工作量估算
- 代码实现：2.5 小时
- 测试编写：1 小时
- 现场调试：2-3 小时
- **总计**：5.5-6.5 小时

### 风险点
- 小口横穿精度（需要现场微调）
- 连续道路切换的状态一致性
- 足球低姿态返回逻辑正确性
