## 1. 背景与目标

赛段6（撷金建功）当前实现为纯里程计八阶段状态机，已在 Gazebo 全程跑通，21 个离线单测通过。
本次改进的唯一目标是**把仿真验证过的逻辑变成真机上能得分的逻辑**。

### 已确认的现场约束

| 约束 | 取值 | 对设计的影响 |
|------|------|--------------|
| 位置数据来源 | 全程连跑，不重置里程计 | seg6 拿到的 `position` 带前五段（含跳跃、上台阶）累积漂移 |
| 计分口径 | **必须球进圈**，无部分分 | 所有容错余量必须押在"把球弄进圈"，包括失败重试 |
| 真机试跑机会 | 很少 | 不能靠现场调参；逻辑本身必须对误差不敏感并能自行兜底 |
| 相机可用性 | 可用，已接通 | `test.py:516` 传 `cam_node.frame` → `test.py:124` 传 `segment6_control(frame=...)` |
| 赛段时间余量 | 宽裕，可重试 3 次 | 重试上限设 3，总超时 120s |

### 当前实现的三个真机隐患

1. **A/B 贴墙判据是绝对坐标**（`y>=14.80`、`x<=0.20`）。漂移偏大 → 狗已顶墙但坐标未达标 →
   持续发前进指令、原地打滑 → **状态机永久卡死**；漂移偏小 → 坐标提前达标、狗离墙尚远就转向 → **顶空**。
2. **D1 顶球成功判据是狗自身位移 ≥0.25m**。狗移动了不等于球被顶出去了。球漏过、顶歪、卡在墙角，
   状态机都照样往下走。
3. **顶球失败没有重试路径**。直接进 E 转身、F 推空气、G 进圈趴下，球仍在角落 → 0 分。

### 方案选择

已评估三种方案：
- **A 闭环重试**（选定）：视觉验球 + 失败回退重顶 + 贴墙停滞判据。
- **B 相对定位**：入段用相机反推里程计漂移偏置，全段判据统一补偿。否决原因：单目测距误差对相机俯仰
  极敏感，估错反而把可用坐标改坏；且顶球失败仍无重试，不解决硬计分口径下的核心风险。
- **C 全程视觉伺服**：彻底不信里程计，视觉追球推球。否决原因：需现场标定伺服增益、处理丢帧与球出视野，
  在"试跑机会很少"前提下翻车概率最高；且放弃了已跑通的两墙自定位这一确定性资产。

选 A 的理由：它是唯一带失败重试的方案，而"必须球进圈"意味着一次顶不中即为零分；视觉只用作**是非判断**
（球是否已离开角落）而非测距，这是单目最可靠的用法；同时保留已仿真验证的八阶段骨架、两墙自定位与
328° 推球几何。

## 2. 状态机设计

### 2.1 关键几何修正：验球时机

顶球姿态为「头朝 225°（西南），用**左侧身体**向机身 +y 方向扫球」，而球位于狗的世界 315°（东南）方向
——与头朝向**相差 90°**，因此**顶球全程相机看不到球**。

验球只能放在 E 段转身到 328° 之后：此时头朝东南，被顶出的球恰落在画面中央偏右。这也让验球与
"对准推球方向"合并为同一动作，不额外消耗时间。

### 2.2 状态流转（10 阶段）

```
A_GO_TOP        转90°贴右墙上行      退出：y>=TOP_Y 或 位移停滞
  ↓
B_GO_CORNER     转180°贴顶墙左行     退出：x<=CORNER_X 或 位移停滞
  ↓
C_AIM_SWEEP     原地转头到 225°      退出：朝向对准（角度取自 RETRY_PROFILE）
  ↓
D1_SWEEP        低重心左横移顶球      退出：位移 >= 阈值（取自 RETRY_PROFILE）
  ↓
D2_CLEAR        低重心右横移拉间隙    退出：位移 >= SWEEP_R_DIST
  ↓
E_FACE_PUSH     原地转身头朝 328°    退出：朝向对准
  ↓
D_VERIFY（新）  连续取帧验球
  ├─ 命中 >=VERIFY_HITS 帧          → F_DRIBBLE（并用 u_offset 微调朝向）
  ├─ 失败且 _attempt+1 < MAX_ATTEMPT  → R_RETURN
  ├─ 失败且 _attempt+1 >= MAX_ATTEMPT → K_AIM（自动切踢球退路）
  └─ frame 为 None（相机故障）      → F_DRIBBLE（降级放行，走纯里程计）
  ↓
R_RETURN（新）  重置为 A_GO_TOP + 清停滞检测器，_attempt += 1 → 回 A/B/C 重顶
  ↓
F_DRIBBLE       锁328°低重心前推      退出：x>=KICK_TRIGGER_X
  ↓
G_THROUGH_GAP   推球穿缝进圈          退出：x>=FINISH_STOP_X
  ↓
TURN_FINISH  →  H_LAYDOWN  →  DONE
```

### 2.3 保留不变的部分

A/B/C/D1/D2/E/F/G 的动作与朝向、两墙自定位机制、328° 推球几何、三个低重心步态（`usergait.toml`
下标 51/52/53）、踢球退路 `K_AIM`/`K_KICK` 的动作骨架。踢球退路由手动开关 `USE_KICK_FALLBACK`
改为**验球重试用尽后自动触发**；该开关保留，置 `True` 时仍可强制走退路。

## 3. 视觉验球

### 3.1 为什么不测距

单目估距靠"已知球径 0.20m + 像素半径"反解，误差对相机俯仰角极敏感。狗在低重心步态下机身俯仰持续摆动，
同一颗球每帧算出的距离可差 30%。而"画面里有没有一个足球大小的圆"这一判断对俯仰摆动几乎免疫，
且恰好就是所需答案：球被顶出角落了吗？

### 3.2 函数契约

替换现有 `detect_ball`，保持 `frame=None` 兼容：

```
find_ball(frame) -> (found: bool, u_offset: float, radius_px: float)
  found      是否找到候选球
  u_offset   球心相对画面中心的横向像素偏移（正=偏右），仅用于微调朝向
  radius_px  像素半径，仅用于过滤噪声，不用于测距
  frame=None → (False, 0.0, 0.0)
```

`find_ball` 为纯函数，无全局状态依赖，可用合成图离线单测。

### 3.3 识别流程（四步过滤）

1. **只看画面下半区** —— 取 `frame[h//2:, :]`。球在地面，天然排除灯光、场外杂物、远景三类误检源。
2. **HSV 阈值分割** —— 阈值抽为模块级常量 `BALL_HSV_LO` / `BALL_HSV_HI`，现场标定只改这两行。
   默认给白球阈值，另备一组亮色球阈值以注释形式并列。
3. **形状与尺寸过滤** —— 对每个轮廓求最小外接圆，要求圆度 `area/(π r²) > BALL_CIRCULARITY_MIN`
   （滤掉细长的黄线、墙缝、阴影带）且 `BALL_MIN_R < r < BALL_MAX_R`（滤掉小噪点与大片高光墙面）。
   取通过过滤的最大轮廓为球。
4. **时间一致性** —— 单帧不作判据，由 `D_VERIFY` 跨帧累计（见 3.4）。

### 3.4 D_VERIFY 判定逻辑

每帧调用 `find_ball`，累计 `_verify_hit` / `_verify_frames`：

| 条件 | 判定 | 动作 |
|------|------|------|
| `_verify_frames >= VERIFY_WINDOW` 且 `_verify_hit >= VERIFY_HITS` | 成功 | 进 `F_DRIBBLE`，用 `u_offset` 微调一次朝向 |
| `_verify_frames >= VERIFY_WINDOW` 且 `_verify_hit < VERIFY_HITS` | 失败 | 进重试判断 |
| `_verify_frames >= VERIFY_MAX_FRAMES` | 超时 | 按失败处理 |
| 首帧 `frame is None` | 降级 | 直接进 `F_DRIBBLE`，走纯里程计 |

常量：`VERIFY_WINDOW = 5`、`VERIFY_HITS = 3`、`VERIFY_MAX_FRAMES = 10`（约 2 秒）。

### 3.5 误检代价分析

误检代价对称，两个方向都不致命：误判成功 → 退化为当前实现的行为；误判失败 → 多顶一次，时间预算够。
最坏情况是 HSV 完全标错导致验球恒失败 → 3 次重试后自动切踢球退路，仍不会零分。

### 3.6 已知局限

- 球被顶得过狠滚出视野会误判失败 → 多顶一次，可接受。
- 不判断球的具体落点，只判在不在视野。落点偏差靠 F/G 段的 328° 朝向锁定补救。

## 4. 贴墙停滞判据

### 4.1 原理

墙的物理位置是可靠的：撞上就走不动了。「走不动」这一信号不依赖任何绝对坐标。

### 4.2 实现

A/B 两段共用一个停滞检测器，与原坐标判据取**或**关系（谁先满足谁生效）：

```
STALL_EPS    = 0.015   # 单帧位移阈值 1.5cm（正常步态 0.20m/s × 0.2s ≈ 4cm）
STALL_FRAMES = 8       # 连续 8 帧 ≈ 1.6 秒

_is_stalled(cur_val, state_key) -> bool
  连续 STALL_FRAMES 帧位移增量都 < STALL_EPS 时返回 True

A 段退出：y >= TOP_Y      or _is_stalled(y, 'A')
B 段退出：x <= CORNER_X   or _is_stalled(x, 'B')
```

`state_key` 使检测器按状态隔离计数，跨状态切换时重置。

### 4.3 参数取值理由

取 8 帧而非 3 帧：低重心步态有迈步周期，单帧位移会周期性接近零；8 帧（1.6s）跨越多个完整步态周期，
只有真被墙挡住才会连续 8 帧不动。代价是撞墙后多顶 1.6 秒——时间宽裕，且顶墙有助于贴紧。

保留坐标判据：坐标准确时它先触发，省去这 1.6 秒。二者为兜底关系而非替换关系。

### 4.4 附带收益

A 段原假设狗从第五段跳下落点（约 x=2.5~2.8）出发贴右墙上行。落点横向偏差会使 B 段左行距离变长，
但 B 段有停滞兜底（撞左墙即停），该偏差被自动吸收，**无需为落点散布单独写补偿逻辑**。
A/B 语义变为"贴着墙走到走不动为止"，起点在哪都收敛到同一角落；`R_RETURN` 复用同一机制，
每次重试都回到同一位置。

### 4.5 仍依赖坐标之处

F 段 `x>=KICK_TRIGGER_X`、G 段 `x>=FINISH_STOP_X`——推球段无墙可撞，只能靠坐标，由第 5 节超时兜底。
停滞检测无法区分"撞墙"与"被球卡住"，后者由 `D_VERIFY` 捕获。

## 5. 重试策略与超时退路

### 5.1 R_RETURN 恢复方式

验球失败说明球仍在角落。此时狗已转到 328° 且 D2 向右退开 15cm，位置与朝向均不适合直接重顶。
恢复不按坐标走回（坐标不可信），而是复用贴墙机制：转 90° 前进至顶墙停滞 → 转 180° 前进至左墙停滞。
这正是 A/B 两段，故实现上只需把 `_state` 置回 `_ST_A_GO_TOP`、重置停滞检测器与验球计数器、
`_attempt += 1`，不新增行走逻辑。

### 5.2 RETRY_PROFILE

每次重试必须改变参数，否则重试等于重复同一失败。顶球失败的两个主因是"扫得不够远，球没出角"
与"扫的位置偏了，从球旁边过去"：侧移量递增解决前者；朝向在 235°/215° 两侧各试一次解决后者。
这是一个小型搜索，而非同一动作重复三遍。

```
RETRY_PROFILE = [
    (0.25, 225),   # 第1次尝试（首顶）：基准
    (0.32, 235),   # 第2次尝试：更朝下，扫得更靠外
    (0.40, 215),   # 第3次尝试：更朝左，扫得更靠里
]
MAX_ATTEMPT = len(RETRY_PROFILE)   # == 3，用尽后自动切踢球退路
```

**计数口径（避免歧义）**：`MAX_ATTEMPT` 计的是**顶球尝试总次数（含首顶）**，即 1 次首顶 + 2 次重顶，
共 3 次尝试；第 4 次不再尝试，直接切踢球退路。`_attempt` 为 0-based 索引，初值 0，
`C_AIM_SWEEP` 的目标朝向与 `D1_SWEEP` 的位移阈值均按 `RETRY_PROFILE[_attempt]` 取值。
`R_RETURN` 执行 `_attempt += 1`；`D_VERIFY` 失败时若 `_attempt + 1 >= MAX_ATTEMPT` 则切退路，
否则进 `R_RETURN`。

### 5.3 三层超时看护

| 层级 | 常量 | 触发后动作 | 兜住的场景 |
|------|------|-----------|-----------|
| 单状态超时 | `STATE_TIMEOUT = 15s` | 强制推进到下一状态 | 停滞检测也失效（如被卡住但里程计仍缓慢累加） |
| 推球段超时 | `PUSH_TIMEOUT = 25s` | 直接进 `TURN_FINISH` → 趴下 | F/G 段无墙可撞、坐标判据不达标 |
| 赛段总超时 | `SEG_TIMEOUT = 120s` | 放弃球，转 328° 前推至停滞或超时后趴下 | 全局兜底 |

赛段总超时是**唯一允许放弃球**的地方。理由：卡死在场上不趴下比球没进圈更糟——后者只丢本段分数，
前者可能让整条赛道无法收尾。

### 5.4 计时实现

用 `time.monotonic()` 记录 `_state_enter_t` 与 `_seg_start_t`，而非按调用次数计数（帧率不稳时
次数计时会失真；第五赛段曾因按次数计时导致起跳过早，已有先例）。`reset_segment6()` 重置全部计时器、
重试计数与验球计数器，保证可重复测试。

### 5.5 失败路径全覆盖

| 故障 | 应对 |
|------|------|
| 顶球没顶出 | 重试 3 次，每次换侧移量与朝向 |
| 重试全败 | 自动切踢球退路 |
| 相机故障（frame 恒 None） | 降级纯里程计，走原流程 |
| 某状态卡死 | 单状态超时强制推进 |
| 推球未到位 | 推球超时，就地趴下 |
| 全局兜底 | 赛段超时，放弃球保完赛 |

## 6. 测试策略

### 6.1 离线单测（扩充 `test_segment6_logic.py`，现有 21 用例全保留）

- **停滞检测**：连续小位移触发 / 正常位移不触发 / 跨状态重置。
- **D_VERIFY**：3/5 命中判成功、2/5 判失败、10 帧超时、`frame=None` 降级放行。
- **尝试计数**：`_attempt` 0→1→2 时 `RETRY_PROFILE` 取值正确；`_attempt` 达 `MAX_ATTEMPT-1`
  且验球失败时切踢球退路（不再进 `R_RETURN`）。
- **R_RETURN**：状态回到 `A_GO_TOP`，停滞检测器与验球计数器已重置。
- **三层超时**：注入伪造时钟（把 `time.monotonic` 替换为可控函数），各自触发正确降级路径。
- **find_ball**：用 numpy 合成图（在纯色背景上画白圆）验证圆度与半径过滤、`frame=None` 分支。

### 6.2 仿真验证（Gazebo）

- `test6.py` 单跑赛段6，确认新状态机不破坏已跑通的全程。
- **主动制造失败**：把球挪开或改大 D1 阈值使其顶空，验证重试确实触发并收敛。
- **注入漂移**：给 `position` 加固定偏置（如 +0.25m），验证停滞判据能救回。
- 传 `frame=None`，验证降级路径仍能完赛。
- 全程串跑 `test.py`，确认 seg5→seg6 衔接与总编排不受影响。

### 6.3 真机（机会有限，只做标定）

1. 拍摄角落里的球与被顶出后的球，离线标定 `BALL_HSV_LO` / `BALL_HSV_HI` 至稳定命中。
2. 记录 seg6 各段实际耗时，据此校准 `STATE_TIMEOUT` / `PUSH_TIMEOUT` / `SEG_TIMEOUT`。

### 6.4 现场清单

**必做**
1. 标定 HSV 两个常量。
2. 校准三个超时常量。

**有机会则做**
3. 记录 seg5 跳下落点 (x, y, 朝向)，确认 A 段起步无异常。
4. 观察一次顶球效果：若首顶即成功，重试路径仅作保险；若失败，确认 `RETRY_PROFILE` 哪一档管用。

相比旧的 6 项采集清单，删去"四边黄线内沿位置"与"球·圈俯视全景"两项——贴墙停滞判据已使 A/B 不依赖
精确边界坐标，这两项测量不再是阻塞项。

### 6.5 无法离线验证的部分

真实地面的顶球物理（摩擦、球的滚动方向）与仿真必然有差异，真实光照下的 HSV 稳定性只能现场标定。
这正是重试机制存在的理由：**不预测物理，而是观测结果并重试**。
